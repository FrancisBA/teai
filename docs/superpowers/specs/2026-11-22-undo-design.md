# Idea Undo — short design

## Intent

`×` and `clear ideas` currently destroy thoughts permanently. One-level undo makes those controls safe without adding accounts, text editing, or multi-select.

This supersedes the earlier "no undo" non-goal for destructive node actions only.

## Goals

- After deleting one idea or clearing all ideas, show a transient Undo affordance that restores the exact prior node array and re-renders the pills.
- Keep snapshot logic pure and testable; keep the UI change inside the existing page and its generated mirror.

## Non-goals

- Multi-level history, redo, undo for recording deletion, undo across page reload, keyboard shortcuts.

## Constraints

- Static serverless page: no build step, no dependencies, no HTTP calls.
- Existing storage key `teai.nodes` and the `isValidNode` node shape are unchanged; positions remain viewport fractions in `[0, 1]`.
- Tests run with `node --test tests/*.test.js`.
- `site/` is generated by `node scripts/sync-site.js` and must stay byte-identical to root sources.
- Do not commit unless the user explicitly asks.
- Existing APIs: `R.removeNode`, `R.clearNodes`, `R.saveNodes`, `R.loadNodes`, `R.moveNode`, `R.nodeHue`; page state `state.nodes`, `nodeLayer`, `renderNode`, `restoreNodes`.
- `attachNodeDrag` mutates node objects in place, so a snapshot must copy each node, not just the array.

## Approaches

- **A. Pure snapshot helper + in-memory toast (picked).** Tiny, testable, no storage schema. Undo lasts until the toast expires or another destructive action replaces it.
- **B. Persist an undo stack in localStorage.** Survives reload but adds schema/versioning and stale-state risk.
- **C. General command history for all mutations.** Too much scope for a one-level need.

## Design

- Add `R.captureNodes(nodes)` returning `nodes.map(node => ({ ...node }))`.
- Add module state `undoSnapshot` and `undoTimer`; add a hidden `#undoToast` with a message and an `undo` button, styled as a bottom-left fixed status strip with `aria-live="polite"`.
- Before delete or clear, set `undoSnapshot = R.captureNodes(state.nodes)`, then mutate and save as today. Show the toast and start a ~6s timer that hides it and clears the snapshot. A new destructive action replaces the snapshot.
- On Undo click: restore `state.nodes = undoSnapshot`, re-render every node, save, hide the toast, and clear the timer/snapshot.
- Add `renderAllNodes()` that clears `nodeLayer` and renders `state.nodes`; use it from Undo and refactor `restoreNodes()` to load saved nodes, update `state.sequence`, and call it.
- Tests: `captureNodes` purity/copy behavior in `tests/resonance.test.js`; source-fragment UI tests for toast markup and undo wiring in `tests/node_management_ui.test.js`; full suite plus `node scripts/sync-site.js`.
