# teai idea-node management design

## Intent

Typed idea nodes can be created but never removed, repositioned, or told apart at a glance. Add a delete control, drag-based node management, and a distinct stable color per node so a thought can be corrected, moved, and recognized, with changes surviving reload.

## Goals

- Delete one idea node from a small control on the node.
- Clear all idea nodes from a button in the tools row.
- Drag a node to a new position; the faint links follow on the next frame.
- Give each node a distinct, stable color derived from its sequence, with no change to the stored node shape.
- Persist deletions and positions under the existing `teai.nodes` localStorage key.
- Keep the ambient, minimal look and the serverless, dependency-free page.

## Non-goals

- Editing the text of an existing node.
- A color picker or user-chosen colors.
- Multi-select, undo, or reordering/z-index controls.
- Any change to the recordings library.
- Any backend, new dependency, or build step.

## Anti-goals

- Turning the idea field into a management dashboard that competes with the recordings library.
- Breaking the existing static Pinokio asset route or the generated `site/` mirror.

## Constraints

- Static page: vanilla JS in `index.html`, pure helpers in `resonance.js`.
- Node shape is validated by `isValidNode`; positions are fractions in `[0, 1]`.
- Tests run with `node --test tests/*.test.js`.
- `site/` is generated by `node scripts/sync-site.js` and must be refreshed after edits.

## Approaches

- **A — in-place controls + drag (chosen):** per-node `×`, a `clear ideas` button, drag to move. Smallest surface and fits the existing pills. Slight clutter on small pills.
- **B — idea list panel:** a second management column like the recordings library. Easier with many ideas, but adds a competing surface and more code.
- **C — typed commands:** `delete`/`clear` in the phrase field. Keyboard-only but undiscoverable and easy to trigger accidentally.

## How

- Add pure helpers to `resonance.js`: `removeNode(nodes, id)`, `clearNodes()`, `moveNode(nodes, id, x, y)` with clamping to `[0, 1]`, and `nodeHue(sequence)` returning a stable hue in `[0, 360)`; export them and unit-test them in `tests/resonance.test.js`.
- In `index.html`, add `clear ideas` to `#tools` and a `×` button inside each rendered node. Use pointerdown/move/up with a small movement threshold so a tap deletes and a drag repositions; set `touch-action: none` on `.node`.
- Set a `--node-hue` CSS custom property from `R.nodeHue(node.sequence)` and use it for each pill's border, background tint, glow, and `×`, keeping text near-white for readability. Deriving hue from `sequence` means existing saved nodes get colors without a schema change.
- Save with `R.saveNodes` after each delete, clear, or drag end. Keep `x`/`y` as viewport fractions so resize preserves relative placement.
- Update `README.md`, refresh `site/` with `node scripts/sync-site.js`, and add markup tests alongside the existing UI tests.

## Left to the builder

- Exact helper signatures and the `clear ideas` label wording.
- Minimal CSS for the `×` affordance, matching the existing `.node` styling.
