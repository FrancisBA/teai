# Idea Undo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let people recover from deleting or clearing idea nodes with one transient Undo action.

**Architecture:** A pure `captureNodes` helper in `resonance.js` snapshots the node array with copied node objects. `index.html` keeps that snapshot in memory, shows a short-lived Undo toast, and restores through a shared `renderAllNodes()` renderer. No persisted history and no new public API beyond the helper.

**Tech Stack:** Vanilla JS, HTML/CSS, Node built-in `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-22-undo-design.md`

## Global Constraints

- Static serverless page: no build step, no dependencies, no HTTP calls.
- Existing storage key `teai.nodes` and the `isValidNode` node shape are unchanged; positions remain viewport fractions in `[0, 1]`.
- Tests run with `node --test tests/*.test.js`.
- `site/` is generated by `node scripts/sync-site.js` and must stay byte-identical to root sources.
- Do not commit unless the user explicitly asks.
- Existing APIs: `R.removeNode`, `R.clearNodes`, `R.saveNodes`, `R.loadNodes`, `R.moveNode`, `R.nodeHue`; page state `state.nodes`, `nodeLayer`, `renderNode`, `restoreNodes`.
- `attachNodeDrag` mutates node objects in place, so a snapshot must copy each node, not just the array.

## Review Focus

- Drag mutates node objects in place, so a snapshot holding references would restore stale positions — pinned by Task 1 `test_capture_nodes_returns_a_new_array_and_new_node_objects`.
- A second destructive action or timer expiry must replace or clear the old snapshot, not stack history — pinned by Task 2 `test_undo_toast_lifecycle`.
- Undo after clear must restore every node and re-render, not append to an empty layer — pinned by Task 2 `test_undo_restores_copied_nodes_rerenders_and_persists`.
- Restored nodes must go back through the existing storage path — pinned by Task 2 `test_undo_restores_copied_nodes_rerenders_and_persists`.
- The hosted `site/` mirror must not drift from root sources — pinned by Task 3's full suite and `node scripts/sync-site.js`.

- [ ] **Step 4: Add undo state and functions**

Next to the `nodeLayer` lookup, look up `undoToast`, `undoMessage`, and `undoButton`, then declare `let undoSnapshot = null` and `let undoTimer = null`.

Define:
- `dismissUndo()`: clears `undoTimer` with `window.clearTimeout`, sets `undoTimer = null`, sets `undoSnapshot = null`, and sets `undoToast.hidden = true`.
- `captureUndo(message)`: sets `undoSnapshot = R.captureNodes(state.nodes)`, writes `message` into `undoMessage.textContent`, sets `undoToast.hidden = false`, clears any existing `undoTimer`, and starts `undoTimer = window.setTimeout(dismissUndo, 6000)`.
- `undoLastAction()`: returns when `undoSnapshot` is null; otherwise sets `state.nodes = undoSnapshot`, calls `renderAllNodes()`, calls `R.saveNodes(state.nodes, localStorage)`, then calls `dismissUndo()`.
- `renderAllNodes()`: calls `nodeLayer.replaceChildren()` and then `renderNode(node)` for each entry in `state.nodes`.
